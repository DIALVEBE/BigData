Fundamentos

¿Qué son los datos y qué es una base de datos?

Foundations

What is data and what is a database?

Un dato es una representación registrable: un nombre, una fecha, una edad, el precio de un producto o la calificación de una película. Una base de datos organiza esos datos para almacenarlos, consultarlos, relacionarlos y actualizarlos.

A datum is a recordable representation: a name, a date, an age, a product price, or a movie rating. A database organizes data so it can be stored, queried, related, and updated.

Bases relacionales y no relacionales

No toda la información se organiza igual. El modelo se elige según el problema, las consultas y las reglas de consistencia.

Relational and Non-Relational Databases

Not all information is organized the same way. The model depends on the problem, the queries, and consistency rules.

Relacionales (SQL) Relational (SQL)

Organizan información en tablas conectadas por claves. Son muy usadas en matrículas, facturación, inventarios y transacciones.

They organize information in tables connected by keys. They are widely used for enrollment, billing, inventory, and transactions.

No relacionales (NoSQL) Non-relational (NoSQL)

Pueden usar documentos, pares clave-valor, grafos o columnas anchas. NoSQL no significa “sin estructura”; significa que no se limita al modelo relacional tradicional.

They may use documents, key-value pairs, graphs, or wide columns. NoSQL does not mean “without structure”; it means not limited to the traditional relational model.

Cuándo pensar relacional When to think relational

Cuando las reglas son claras, las relaciones importan y se requiere consistencia: pagos, matrículas, inventarios, historias de cambios o trazabilidad.

When rules are clear, relationships matter, and consistency is required: payments, enrollments, inventories, change history, or traceability.

Cuándo pensar no relacional When to think non-relational

Cuando los documentos cambian con frecuencia, se consulta por clave, se modelan redes o se necesita absorber eventos con estructura flexible.

When documents change frequently, data is queried by key, networks are modeled, or events with flexible structure must be absorbed.

Decisión práctica Practical decision

No se elige por moda. Se elige por preguntas, volumen, latencia, reglas, equipo, costos y mantenimiento.

It is not chosen by trend. It is chosen by questions, volume, latency, rules, team, cost, and maintenance.

Relaciones y claves

Las claves permiten conectar tablas sin repetir todos los datos en cada registro.

Relationships and Keys

Keys connect tables without repeating all data in every record.

PK

La clave primaria identifica de forma única cada fila de una tabla.

The primary key uniquely identifies each row in a table.

FK

La clave foránea referencia una clave de otra tabla.

The foreign key references a key from another table.

1:N

Un cliente puede tener muchos pedidos; cada pedido pertenece a un cliente.

One customer can have many orders; each order belongs to one customer.

Studentsstudent_id PK · name
Enrollmentsstudent_id FK · course_id FK · term
Coursescourse_id PK · name
RelaciónRelationshipMuchos a muchos mediante tabla intermedia.Many-to-many through an intermediate table.
ReglaRuleCada inscripción referencia registros existentes.Each enrollment references existing records.

Importante: si `id_cliente = 1` aparece en dos pedidos, eso no es necesariamente un duplicado. Puede representar dos compras legítimas de la misma persona.

Important: if `customer_id = 1` appears in two orders, that is not necessarily a duplicate. It may represent two legitimate purchases by the same person.

Normalization: organizing to avoid problems

La normalización separa entidades y relaciones para reducir redundancias innecesarias. Evita errores de actualización, inserción y eliminación cuando un dato se repite sin control.

Normalization separates entities and relationships to reduce unnecessary redundancy. It prevents update, insertion, and deletion problems when data is repeated without control.

Anomalía de actualización Update anomaly

Si el nombre de un programa está repetido en 500 filas, corregir una tilde puede dejar valores distintos si no se actualiza todo.

If a program name is repeated in 500 rows, fixing one accent may leave different values if not every row is updated.

Anomalía de inserción Insertion anomaly

Si los programas solo existen dentro de filas de estudiantes, no podríamos registrar un programa nuevo hasta tener estudiantes.

If programs only exist inside student rows, we could not register a new program until it has students.

Anomalía de eliminación Deletion anomaly

Si borramos el único estudiante de un programa, podríamos perder accidentalmente la información del programa.

If we delete the only student in a program, we might accidentally lose the program information.

¿Qué es SQL?

SQL permite consultar, insertar, actualizar y eliminar información. En esta sesión trabajamos consultas sin modificar datos.

What is SQL?

SQL lets us query, insert, update, and delete information. In this session we query data without modifying it.

Una consulta básica responde: qué quiero ver, de qué tabla viene, qué condición debe cumplir y cómo quiero ordenar el resultado. SQL no es solamente sintaxis: es una forma de convertir preguntas de negocio en operaciones sobre datos.

A basic query answers: what I want to see, which table it comes from, what condition it must satisfy, and how I want the result sorted. SQL is not only syntax: it is a way to turn business questions into operations over data.

SELECT nombre, ciudad, promedio
FROM Estudiantes
WHERE ciudad = 'Tunja' AND promedio >= 4.0
ORDER BY promedio DESC;

Esta consulta se leería así: muestra estudiantes de Tunja con promedio igual o superior a 4.0, ordenados de mayor a menor promedio. La convención de escribir palabras clave en mayúsculas mejora la lectura; para textos usamos comillas simples.

This query reads as: show students from Tunja with GPA equal to or above 4.0, sorted from highest to lowest GPA. The convention of writing keywords in uppercase improves readability; text values use single quotes.

Universidad: seguimiento académico University: academic monitoring

Coordinación quiere identificar estudiantes activos de Ingeniería de Sistemas con promedio alto para invitarlos a monitorías.

Coordination wants to identify active Systems Engineering students with high GPA to invite them to tutoring roles.

SELECT nombre, semestre, promedio
FROM Estudiantes
WHERE programa = 'Ingeniería de Sistemas'
  AND estado = 'Activo'
  AND promedio >= 4.2
ORDER BY promedio DESC;
Tienda: inventario crítico Store: critical inventory

El área de compras necesita saber qué productos tienen pocas unidades y se venden con frecuencia.

The purchasing area needs to know which products have few units and sell frequently.

SELECT producto, categoria, stock, ventas_mes
FROM Inventario
WHERE stock <= 10
  AND ventas_mes >= 50
ORDER BY stock ASC, ventas_mes DESC;

Un centro médico quiere priorizar citas pendientes de pacientes mayores de 60 años.

A medical center wants to prioritize pending appointments for patients over 60 years old.

INNER JOIN: unir información relacionada

Two tables

INNER JOIN: combining related information

`INNER JOIN` conserva las filas que encuentran coincidencia según la condición `ON`. Si una inscripción apunta a una asignatura inexistente, no aparecerá en el resultado del cruce; por eso la integridad referencial es tan importante.

`INNER JOIN` keeps rows that find a match according to the `ON` condition. If an enrollment points to a nonexistent course, it will not appear in the joined result; that is why referential integrity matters so much.

Estudiantesid_estudiante PK · nombre · programa
Inscripcionesid_estudiante FK · id_asignatura FK · nota
ONEstudiantes.id_estudiante = Inscripciones.id_estudiante
INNER JOINSolo coincidenciasMatches only
SELECTNombre, asignatura, notaName, course, grade
SELECT Estudiantes.nombre, Inscripciones.id_asignatura, Inscripciones.nota
FROM Estudiantes
INNER JOIN Inscripciones
ON Estudiantes.id_estudiante = Inscripciones.id_estudiante;
SELECT Estudiantes.nombre, Asignaturas.nombre AS asignatura, Inscripciones.nota
FROM Estudiantes
INNER JOIN Inscripciones
ON Estudiantes.id_estudiante = Inscripciones.id_estudiante
INNER JOIN Asignaturas
ON Inscripciones.id_asignatura = Asignaturas.id_asignatura
WHERE Estudiantes.programa = 'Ingeniería de Sistemas'
ORDER BY Inscripciones.nota DESC;

Plantilla de consulta

No necesitas usar todas las cláusulas en cada consulta. Empieza por `SELECT` y `FROM`, y añade lo necesario.

Query Template

You do not need every clause in every query. Start with `SELECT` and `FROM`, then add what you need.

FROM table1
INNER JOIN table2
ON table1.id = table2.related_id
