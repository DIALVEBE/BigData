Riesgos frecuentesCommon risks

Data swamp sin dueño ni catálogo; deriva semántica (dos áreas cuentan “contratos” distinto); esquemas que rompen tableros; duplicación por reintentos; filtración en notebooks o exportaciones; sesgo territorial; dependencia del proveedor.

A data swamp without owners or catalog; semantic drift (teams count “contracts” differently); schema changes that break dashboards; duplicates from retries; leaks in notebooks or exports; geographic bias; vendor lock-in.

Gobernanza como código: convertir reglas aprobadas en validaciones de esquema, controles de acceso, retención, pruebas y alertas reproducibles. El código ejecuta la regla; no determina si la regla es jurídicamente o éticamente correcta.

Governance as code: express approved rules as reproducible schema checks, access controls, retention settings, tests, and alerts. Code enforces a rule; it does not decide whether the rule is legally or ethically sound.

¿Qué significa gobernar los datos?

Un sistema de decisiones, responsabilidades, políticas y controles que define cómo se obtienen, describen, protegen, transforman, comparten y conservan los datos.

What does it mean to govern data?

A system of decisions, responsibilities, policies, and controls that defines how data is acquired, described, protected, transformed, shared, and retained.

Etapas del ejercicio gobernado

Governed exercise stages

  1. Comprender: registra ID, URL, organismo, fecha de consulta, cadencia indicada, cobertura, licencia, columnas y conteo visible (dinámico).
  2. Perfilar: elige muestra/subconjunto reproducible; declara filtros y fecha de corte; mide nulos, formatos, categorías, precios no interpretables y duplicados con clave aprobada.
  3. Clasificar: identifica campos personales y justifica cuáles necesita el propósito; el producto agregado debe excluir identificadores innecesarios.
  4. Definir respuesta a fallos: ID nulo: cuarentena crítica; modalidad fuera de catálogo: advertencia y homologación; precio extraño: revisar fuente, no corregir por intuición; esquema cambiado: detener promoción hasta revisión.
  5. Publicar: reconciliación, Owner aprobador, privacidad revisada, ficha metodológica, fecha de corte, fuentes, filtros, limitaciones y mecanismo de reporte.
  1. Understand: record dataset ID, URL, agency, access date, stated cadence, coverage, license, columns, and visible count (dynamic).
  2. Profile: choose a reproducible sample/subset; record filters and cutoff date; measure nulls, formats, categories, uninterpretable prices, and duplicates using an approved key.
  3. Classify: identify personal fields and justify which the purpose needs; the aggregated product should exclude unnecessary identifiers.
  4. Define failure handling: null ID: critical quarantine; unknown method: warning and mapping; unusual price: inspect source, do not guess; changed schema: stop promotion pending review.
  5. Publish: reconcile, obtain Owner approval, review privacy, and attach method sheet, cutoff date, sources, filters, limitations, and feedback channel.

Umbrales solo para debatir: ID completo ≥99,9 %, precios no interpretables ≤1 %, metadatos requeridos 100 %. Son metas propuestas para el ejercicio, no estándares ni requisitos oficiales.

Discussion thresholds only: ID completeness ≥99.9%, uninterpretable prices ≤1%, required metadata 100%. These are proposed exercise targets, not official standards or requirements.

Segundo referente: DANE y Sistema Estadístico Nacional

Second reference: DANE and the National Statistical System

La Ley 2335 de 2023 establece el marco de estadísticas oficiales, reconoce el papel técnico del DANE y trata coordinación, estándares, calidad, registros administrativos, metadatos y reserva estadística. Este referente muestra gobernanza interinstitucional. Sus reglas no convierten todo conjunto de datos de cualquier entidad en estadística oficial ni habilitan usar información confidencial para evaluar personas individualmente.

Law 2335 of 2023 establishes the official statistics framework, recognizes DANE's technical role, and addresses coordination, standards, quality, administrative records, metadata, and statistical confidentiality. It illustrates inter-agency governance. It does not make every dataset official statistics or allow confidential data to be used to assess individuals.
